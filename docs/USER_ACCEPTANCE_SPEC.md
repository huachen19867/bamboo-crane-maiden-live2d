# 竹鹤少女｜老板的质量验收要求

> 建立日期：2026-08-26。本文是后续建模、评审和交付的最高项目质量基准；旧网页原型、自动拆层报告和可播放但观感不合格的 Cubism MVP 均不能降低这些要求。

## 目标不是“图片会动”

最终交付必须是一位完整、连续、可操演的 Live2D 角色，而不是把参考图切成若干 PNG 后旋转或平移。制作工具以 Live2D Cubism Editor 为准；网页、Viewer、动捕和时间轴是运行时与验收环境，不能代替 Cubism 内的连续建模。

角色首先要像参考图中的同一个人：脸型、眼睛比例、发型、服装、鹤纹、色彩、整体剪影和气质不能因为拆层或动画而失真。中性姿态的目标是与参考角色不低于 95% 的相似度，但该数值必须来自真实分层合成后的角色区域比对，并额外通过人工面部与全身剪影检查；直接把参考整图画回画布不构成证据。动态姿态另行验收，不能用静态高分掩盖运动时的断裂或走样。

## 不可接受的视觉问题

静止和运动都不得有“拼图”“贴纸”“纸片绕轴转”的观感。手、手臂、躯干、腰髋、双腿、衣摆、披帛和头发必须看作同一角色的连续体；局部纹理可独立，但在关节处必须有足够底绘、重叠、遮挡和体积修形。

眼睛不能变成脱离参考脸型的夸张大眼。瞳孔、虹膜与高光必须位于眼睑的裁切关系内；眨眼是眼睑合拢，而不是睁眼贴图淡出、闭眼贴图淡入。任何眼睛大小、位置、饱和度、高光和睫毛的调整都以参考图面部比例为准，先单独通过面部审阅，再进入动作。

Rotation Deformer 只能表达骨骼方向，不能充当关节最终形状。肩、肘、腕、髋、膝、踝的最终效果必须由局部 Warp 网格、三姿态以上的关键形、底绘与必要的 Glue / Mask / Draw Order 共同完成。只要肉眼能看出整块图绕一点转动，该动作即判失败，不得以“幅度已缩小”通过。

## 全身、物理与待机要求

镜头保持固定。待机不允许只剩眨眼：角色需有克制的呼吸、重心与头部微动，头发、衣袖、裙摆和披帛有各自的二次运动。默认眨眼周期为 1.52 秒，容差不超过 0.1 秒。

全身动作至少覆盖头部三轴、躯干、左右肩肘腕和手势、骨盆、左右髋膝踝、脚接触与支撑脚切换。腿脚不是整人平移的附属品；任何步态都必须能解释骨盆重心、抬腿、膝弯、脚底接触和落脚。

风场的目标观感是颈后方来风、约 1.2 m/s、6% 湍流下的细微不一致摆动。实现可以把发丝聚合成发束，不能虚构 2000 根独立 2D 网格；但必须在 Cubism Physics 或等价分段物理链中真实配置根部、过渡段和末端。服装锚点应稳定，只有自由端受风、回弹和阻尼影响，不能让整件衣服像硬纸片一起转。

## 操演与玩法要求

成品需支持四类驱动，而且它们必须映射到同一套 Cubism 参数：自动待机、键鼠/手柄操演、摄像头或 OSC 动捕、时间轴演出。动捕至少接管头、脸、上半身与手臂；键鼠与手柄可局部覆盖；腿脚和复杂手势可由操演快捷键或时间轴控制。网页原型里的这些交互思路可以复用，但不得直接操作 PNG 图层。

## 交付与质量门

在导出前，必须先给老板看中性图、脸部特写，以及每个已完成关节的中间值和正反极值。没有通过肉眼评审，不能以自动化测试、文件存在或“Viewer 能打开”宣布完成。

正式运行时包至少包含由当前官方 Editor 导出的 `.moc3`、`.model3.json`、纹理、`.cdi3.json`，以及实际建立后导出的 `.physics3.json`；动作、表情、点击区域和输入映射按已完成范围登记。每一项只能报告已验证的状态；缺少 Physics、肘腕或腿脚时必须直说“未完成”，不能用 MVP、参数名或旧网页能力暗示已经具备。

工作节奏可以快，但检查点应放在美术质量、保存、导出和实际播放上，而不是每个鼠标点击。遇到无法同时满足质量、范围和时间时，必须在继续投入前向老板说明真实代价与可选范围，不能静默降低成品标准。
